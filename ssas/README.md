# HNH_Analytics — SSAS Tabular model

Spec: `docs/superpowers/specs/2026-10-07-hnh-ssas-tabular-model-design.md`. Server `HNHANALYTICSSRV\REPORTSERVERDB`
(SQL Server 2025 Analysis Services, compatibility level 1700). Power BI Report Server reports connect live.

**HNHANALYTICSSRV is the production server.** The working copy `D:\new_dwh_modeling` is on it. Every deploy, process,
restore or drop changes the production instance; the test slot `HNH_Analytics_Test` is on the same instance.

## Layout

| Path | What |
|---|---|
| `HNH_Analytics/` | TMDL model. Tables, relationships, perspectives, `model.tmdl` and `database.tmdl` are generated by `tools/generate.py`; `roles/`, `tables/Time Calculation.tmdl`, `tables/_Measures.tmdl` (every measure) and hierarchies are hand-written and kept by the generator. |
| `tools/` | `model_config.py` (tables, relationship rules, perspectives), `generate.py`, `hnh_tmdl.py` + tests (`python -m pytest ssas/tools`). |
| `bpa_rules.json` | Best Practice Analyzer rules; any error stops a deploy. |
| `scripts/` | `deploy.ps1`, `partitions.ps1`, `process.ps1`, `test.ps1`, module `HnhSsas.psm1` + Pester tests. Windows PowerShell 5.1. |
| `tests/` | `security.json` (test logins), `measures/*.json` (DAX vs SQL checks), `performance.json`. |
| `logs/`, `state/` | Created on the server, not in git. |

## Prerequisites on the server

- Tabular Editor 2.27 in `C:\Program Files (x86)\Tabular Editor` (or pass `-TabularEditorDir`).
- ClickHouse ODBC driver (64-bit) and system DSN `HNH_Gold` → database `gold`, user `bi_user` (`max_execution_time` 3600).
  The model reads it through Power Query (`Odbc.Query("dsn=HNH_Gold", …)`), not `MSDASQL`, which loses decimal
  fractions and Arabic text with this driver (spec P24).
- MSOLAP OLE DB provider (installed with SSMS or the AS client libraries).
- Local group `HNHANALYTICSSRV\HNH_BI_Users`; every report user is a member and has rows in `gold.sec_user_access`.
- Run every script in Windows PowerShell as an SSAS server administrator: `powershell -ExecutionPolicy Bypass -File ssas\scripts\<script>.ps1 …`.

## Change the model

1. Columns changed in a `gold.ssas_*` view → `python scripts/gen_view_contracts.py`, then `python ssas/tools/generate.py`. Without `clickhouse_connect` (the server), run `python ssas/tools/generate.py --from-contracts` after updating `_ssas__models.yml`.
2. Measures: edit `tables/_Measures.tmdl` (`measure` blocks, `///` description, `formatString`, `displayFolder`). The display folder is `<domain>\<topic>`, where the domain is a perspective name (`Patient Flow`, `Revenue Cycle`, `Claims & Pre-auth`, `Finance`, `Workforce`, `Supply Chain`, `Patient Experience`, `Balanced Scorecard`) or `Diagnostics`; each perspective shows its domain's measures (`PERSPECTIVE_MEASURE_DOMAINS` in `tools/model_config.py` for Executive and Patient Details). New snapshot measures carry `annotation hnh_snapshot = 1` and are added to the list in every `ISSELECTEDMEASURE` of `tables/Time Calculation.tmdl`. Every measure needs at least one check in `tests/measures/<domain>.json` (`allow_zero: true` only where blank is the intended answer). After editing measures run `python ssas/tools/measure_guards.py` (wraps every measure in its "can't be analysed by" guard, P41) and then `python ssas/tools/sync_perspectives.py`. Edit a measure's own expression between `VAR __Value = ( -- measure body` and `) -- end of measure body`.
3. Check offline: `TabularEditor.exe ssas\HNH_Analytics -A ssas\bpa_rules.json -V` (no `type=error`), `python -m pytest ssas/tools`, `Invoke-Pester -Script ssas\scripts` (all Pester files).
4. Run `deploy.ps1 -Stage All` from the working copy on the server (no copy step).

## Balanced scorecard

Perspective `Balanced Scorecard` (spec `docs/superpowers/specs/2026-10-20-hnh-bsc-ssas-perspective-analysis.md`):
- **Formulas** are the measures in folder `Balanced Scorecard\…` of `tables/_Measures.tmdl`: one measure per KPI, the
  dispatchers `BSC Actual` and `BSC Target`, the scoring measures, and the visual's `BSC Visual Payload` (overview,
  board, owner pages) and `BSC Visual Payload Scores` (hospital comparison page). The dispatchers and the measures that
  inline them (`BSC Variance %`, `BSC Score`, `BSC State` and both payloads) each hold the KPI list twice: a
  `ROW ( "@<CODE>", [<measure>], … )` table and a `SWITCH ( Code, "<CODE>", MAXX ( …, [@<CODE>] ), … )` lookup.
  `BSC Visual Payload` has a third list, `ADDCOLUMNS ( VALUES ( 'Date'[Year Month] ), … )`, that evaluates its 24 trend
  months in one go, and its lists call `[_Unguarded <measure>]`: hidden copies of the KPI and budget measures without
  their inner guards (the payload's own guard covers their facts), which `tools/measure_guards.py` writes for every
  `_Unguarded` name a measure references. Both make the overview faster for users with row-level security, whose
  patient-linked queries are never served from the cache.
  `tools/gen_bsc_kpi_lists.py` writes all of them from its `KPIS` and `BUDGETS` lists. To add a KPI:
  1. Add its row to the catalogue (`default.map_bsc_kpi`, `docs/bsc_config.md`).
  2. Add its measure (`BSC <name>`, folder `Balanced Scorecard\<pillar>`) and, for a budget target, its
     `BSC Target <name>` measure (folder `Balanced Scorecard\Targets`).
  3. Add `("<CODE>", "<measure>")` to `KPIS` in `tools/gen_bsc_kpi_lists.py` (and to `BUDGETS` for a budget target),
     and the KPI's numerator and denominator to `PARTS` in `tools/bsc_kpi_parts.py` (or, when its actual is not a
     ratio, growth or value, a reason to `NO_PARTS` and to the list below), then run
     `python ssas/tools/gen_bsc_kpi_lists.py`. A growth, value or no-parts KPI also goes into the `c IN { … }` lists
     of the two `BSC Numerator and BSC Denominator rebuild BSC Actual` checks.
  4. Run `python ssas/tools/measure_guards.py` (it also writes the payload's `_Unguarded` copy of the new measure),
     then `python ssas/tools/sync_perspectives.py`.
  5. Add a check for the new measure in `tests/measures/balanced_scorecard.json`.
  6. Run `python -m pytest ssas/tools`; `test_bsc_kpi_lists_agree` fails when a list is missing the KPI, and
     `test_gen_bsc_kpi_lists.py` when the generator was not run. Then deploy.
- **Numerator and denominator** of the KPI in context (KPI Detail page): `BSC Numerator` and `BSC Denominator`
  (folder `Balanced Scorecard\Scoring`), written whole by `tools/gen_bsc_kpi_lists.py` from `PARTS` in
  `tools/bsc_kpi_parts.py`. They evaluate the KPI's parts in the filter context `BSC Actual` gives its measure (days
  up to today, hospitals only), blank for a parked KPI; a manual KPI's parts are the summed `BSC Manual Values`
  numerator and denominator (a denominator of 0 is outpatient + ER visits). `BSC Actual` is numerator ÷ denominator
  (ratio), numerator ÷ denominator − 1 (growth: `INT_ER_GROWTH`) or the numerator alone (value: `FIN_NET_REVENUE`,
  `FIN_REVENUE_GROWTH`, whose actual is the revenue, `CUS_PAYER_VOLUME`, `INT_PATIENT_VOLUME`; no denominator). An average (`CUS_OP_WAIT`, `INT_ALOS`, `INT_APPROVAL_TAT`,
  `LRN_TIME_TO_FILL`) is the sum over the count of the same column, and `CUS_PATIENT_SATISFACTION` (Overall
  Satisfaction (0-100)) the rescaled scored answers over their count. Every KPI has parts (`NO_PARTS` is empty).
- **Settings** (catalogue, targets, weights, thresholds, owners, categories, parameters, manual values) are rows in the
  ClickHouse `default.map_bsc_*` tables, edited by the BI manager (`docs/bsc_config.md`). They reach the model through
  the nightly build and `process.ps1 -Mode Daily`; no deploy is needed.

## Run

| Task | Command |
|---|---|
| Deploy (validate, test, promote) | `deploy.ps1 -Stage All`. Validate = Best Practice Analyzer. Test reuses the loaded `HNH_Analytics_Test` (metadata, new or changed tables, Daily refresh); add `-Full` to reload it from scratch (after a long gap, or when an old month's row count fails). The test database stays loaded after promotion. |
| Try measure changes on the test database | `deploy.ps1 -Stage TestMeasures` (validate, metadata to `HNH_Analytics_Test` keeping its data, load unprocessed partitions, measure checks). The first run after a promotion loads the whole test database. |
| After each successful dbt run | `process.ps1 -Mode Daily` (exit 2 = gate closed: no new successful `tag:hnh` run; `-Selected '<selector>'` when the dbt run used another selector) |
| Friday | `process.ps1 -Mode Weekly` |
| In January (partition roll-over) | After `process.ps1 -Mode Daily`, run `test.ps1 -Database HNH_Analytics -Stage RowCounts`. |
| Test production | `test.ps1 -Database HNH_Analytics` |
| Partition preview | `partitions.ps1 -Database HNH_Analytics -DryRun` |
| Roll back | `deploy.ps1 -Stage Rollback -BackupFile HNH_Analytics_<timestamp>.abf` (last 5 backups kept in the SSAS backup folder) |

## Trigger from Dagster

Dagster on the dbt server (172.22.25.214) runs `process.ps1` over SSH after its dbt job, as the local account
`HNHANALYTICSSRV\svc_dagster` (an SSAS server administrator, member of `OpenSSH Users`, key-only login; sshd listens on
port 22 for that host only; set up 2026-11-01). The gate inside the script decides whether anything is processed, so
the asset may run after every dbt job; exit code 2 is reported as "nothing new", not as a failure.

1. Copy the private key `C:\HNH\secrets\svc_dagster_id_ed25519` to the Dagster host as `~/.ssh/svc_dagster_id_ed25519`
   (mode 600) of the account that runs Dagster. Check: `ssh -i ~/.ssh/svc_dagster_id_ed25519 svc_dagster@hnhanalyticssrv whoami`.
2. Add `dagster/hnh_analytics_refresh.py` to the Dagster project and merge its `defs`. Set `HNH_DBT_DEPS` to the dbt
   asset keys of the hnh models and, when the dbt job does not run `tag:hnh`, the `selected` config to its selector
   (the gate reads `gold.ssas_etl_run_log.selected`). Either add the asset to the dbt job's selection or keep the
   module's schedules (Daily 03:00, Weekly on Friday).
3. `process.ps1` writes its transcript to `ssas/logs/` and the last processed run to `ssas/state/<database>.json`
   (`svc_dagster` has Modify on both); it reads ClickHouse through the system DSN `HNH_Gold`.

The public key is `C:\ProgramData\ssh\svc_dagster_authorized_keys` (`Match User svc_dagster` in `sshd_config`,
Windows Server 2025 also requires the `OpenSSH Users` group); to rotate, `ssh-keygen` a new pair into
`C:\HNH\secrets\` and replace that file (owner Administrators, SYSTEM and Administrators full, svc_dagster read).

## Give a user access

`bi_users.csv` in the repository root (not in git) is the list of report users: login, department, name, branch,
specialty, `is_admin`, `can_see_pay`, `can_see_pii`.

The server joined the domain `HnhRiyadh.com` in October 2026. A report user is either a **local account**,
`HNHANALYTICSSRV\<name>` (the original design: created by step 2), or a **domain account** written as its user
principal name, `<name>@hnhriyadh.com`. The `HNH Readers` role compares `USERPRINCIPALNAME()`, which is the UPN for a
domain account, so a domain reader whose UPN has no row in `bi_users.csv` sees no branch at all: every branch-linked
measure is blank and a custom visual draws nothing (found 2026-10-29 with `HNHRIYADH\InmaMedAuditor`). Check the exact
string with the measure `_Measures[Current User]` as that user.

1. Add or change the user's row in `bi_users.csv` (a domain account: UPN as `login_name`, `dep`, name, branches, flags).
2. `scripts\create_bi_windows_users.ps1` creates the local Windows account (random password, never expires), and puts it
   in `HNH_BI_Users`, in the department group `HNH_BI_<dep>` and in the branch group `HNH_BI_Branch_<branch>` of every
   branch the user can see (all eight without `branch_key`). The script only adds memberships; after moving a user
   to another branch or department, remove the old group membership by hand. New passwords go to `C:\HNH\secrets\` (Administrators
   only): `bi_user_passwords.csv` to hand out, `bi_user_credentials.xml` for `test.ps1`. A domain account gets no local
   account or password; the script only puts it in `HNH_BI_Users` and its department and branch groups.
3. `scripts\load_bi_users.ps1` (ClickHouse admin login) replaces `default.bi_users` and `default.map_bi_user_permission`
   with the CSV, after copying the old rows to `*_backup_<timestamp>` tables.
4. After the next dbt build and `process.ps1 -Mode Daily`, the measure `_Measures[Current User]` (folder Diagnostics) in a report shows `HNHANALYTICSSRV\<user>` for a local account and `<name>@hnhriyadh.com` for a domain account.

Model administrators (role `HNH Admins`, no row filters) are listed in `$admins` in `scripts\deploy.ps1`, which adds
them to `HNH_Analytics` and `HNH_Analytics_Test` after every deploy.

A row without `branch_key` sees every branch, Head Office included: `load_bi_users.ps1` loads it with `IsAdmin = 1`. Its
specialty restriction and its pay and PII flags still apply.
