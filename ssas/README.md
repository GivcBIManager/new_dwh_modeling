# HNH_Analytics — SSAS Tabular model

Spec: `docs/superpowers/specs/2026-10-07-hnh-ssas-tabular-model-design.md`. Server `HNHANALYTICSSRV\REPORTSERVERDB`
(SQL Server 2025 Analysis Services, compatibility level 1700). Power BI Report Server reports connect live.

**HNHANALYTICSSRV is the production server.** The working copy `D:\new_dwh_modeling` is on it. Every deploy, process,
restore or drop changes the production instance; the test slot `HNH_Analytics_Test` is on the same instance.

## Layout

| Path | What |
|---|---|
| `HNH_Analytics/` | TMDL model. Tables, relationships, perspectives, `model.tmdl` and `database.tmdl` are generated by `tools/generate.py`; `roles/`, `tables/Time Calculation.tmdl`, `tables/_Measures.tmdl` (every measure) and hierarchies are hand-written and kept by the generator. |
| `tools/` | `model_config.py` (tables, relationship rules, perspectives), `generate.py`, `hnh_tmdl.py` + tests (`python -m pytest ssas/tools`). |
| `bpa_rules.json` | Best Practice Analyzer rules; any error stops a deploy. |
| `scripts/` | `deploy.ps1`, `partitions.ps1`, `process.ps1`, `test.ps1`, module `HnhSsas.psm1` + Pester tests. Windows PowerShell 5.1. |
| `tests/` | `security.json` (test logins), `measures/*.json` (DAX vs SQL checks), `performance.json`. |
| `logs/`, `state/` | Created on the server, not in git. |

## Prerequisites on the server

- Tabular Editor 2.27 in `C:\Program Files (x86)\Tabular Editor` (or pass `-TabularEditorDir`).
- ClickHouse ODBC driver (64-bit) and system DSN `HNH_Gold` → database `gold`, user `bi_user` (`max_execution_time` 3600).
  The model reads it through Power Query (`Odbc.Query("dsn=HNH_Gold", …)`), not `MSDASQL`, which loses decimal
  fractions and Arabic text with this driver (spec P24).
- MSOLAP OLE DB provider (installed with SSMS or the AS client libraries).
- Local group `HNHANALYTICSSRV\HNH_BI_Users`; every report user is a member and has rows in `gold.sec_user_access`.
- Run every script in Windows PowerShell as an SSAS server administrator: `powershell -ExecutionPolicy Bypass -File ssas\scripts\<script>.ps1 …`.

## Change the model

1. Columns changed in a `gold.ssas_*` view → `python scripts/gen_view_contracts.py`, then `python ssas/tools/generate.py`. Without `clickhouse_connect` (the server), run `python ssas/tools/generate.py --from-contracts` after updating `_ssas__models.yml`.
2. Measures: edit `tables/_Measures.tmdl` (`measure` blocks, `///` description, `formatString`, `displayFolder`). The display folder is `<domain>\<topic>`, where the domain is a perspective name (`Patient Flow`, `Revenue Cycle`, `Claims & Pre-auth`, `Finance`, `Workforce`, `Supply Chain`, `Patient Experience`, `Balanced Scorecard`) or `Diagnostics`; each perspective shows its domain's measures (`PERSPECTIVE_MEASURE_DOMAINS` in `tools/model_config.py` for Executive and Patient Details). New snapshot measures carry `annotation hnh_snapshot = 1` and are added to the list in every `ISSELECTEDMEASURE` of `tables/Time Calculation.tmdl`. Every measure needs at least one check in `tests/measures/<domain>.json` (`allow_zero: true` only where blank is the intended answer). After editing measures run `python ssas/tools/measure_guards.py` (wraps every measure in its "can't be analysed by" guard, P41) and then `python ssas/tools/sync_perspectives.py`. Edit a measure's own expression between `VAR __Value = ( -- measure body` and `) -- end of measure body`.
3. Check offline: `TabularEditor.exe ssas\HNH_Analytics -A ssas\bpa_rules.json -V` (no `type=error`), `python -m pytest ssas/tools`, `Invoke-Pester -Script ssas\scripts` (all Pester files).
4. Run `deploy.ps1 -Stage All` from the working copy on the server (no copy step).

## Balanced scorecard

Perspective `Balanced Scorecard` (spec `docs/superpowers/specs/2026-10-20-hnh-bsc-ssas-perspective-analysis.md`):
- **Formulas** are the measures in folder `Balanced Scorecard\…` of `tables/_Measures.tmdl`: one measure per KPI, the
  dispatchers `BSC Actual` and `BSC Target`, and the scoring measures. A new KPI needs its measure, a line in the
  `SWITCH` of `BSC Actual` (and `BSC Target` for a budget target), a check in `tests/measures/balanced_scorecard.json`,
  and a deploy.
- **Settings** (catalogue, targets, weights, thresholds, owners, categories, parameters, manual values) are rows in the
  ClickHouse `default.map_bsc_*` tables, edited by the BI manager (`docs/bsc_config.md`). They reach the model through
  the nightly build and `process.ps1 -Mode Daily`; no deploy is needed.

## Run

| Task | Command |
|---|---|
| Deploy (validate, test, promote) | `deploy.ps1 -Stage All`. Validate = Best Practice Analyzer. Test reuses the loaded `HNH_Analytics_Test` (metadata, new or changed tables, Daily refresh); add `-Full` to reload it from scratch (after a long gap, or when an old month's row count fails). The test database stays loaded after promotion. |
| Try measure changes on the test database | `deploy.ps1 -Stage TestMeasures` (validate, metadata to `HNH_Analytics_Test` keeping its data, load unprocessed partitions, measure checks). The first run after a promotion loads the whole test database. |
| After each successful dbt run | `process.ps1 -Mode Daily` (exit 2 = gate closed: no new successful `tag:hnh` run) |
| Friday | `process.ps1 -Mode Weekly` |
| In January (partition roll-over) | After `process.ps1 -Mode Daily`, run `test.ps1 -Database HNH_Analytics -Stage RowCounts`. |
| Test production | `test.ps1 -Database HNH_Analytics` |
| Partition preview | `partitions.ps1 -Database HNH_Analytics -DryRun` |
| Roll back | `deploy.ps1 -Stage Rollback -BackupFile HNH_Analytics_<timestamp>.abf` (last 5 backups kept in the SSAS backup folder) |

## Give a user access

`bi_users.csv` in the repository root (not in git) is the list of report users: login, department, name, branch,
specialty, `is_admin`, `can_see_pay`, `can_see_pii`.

1. Add or change the user's row in `bi_users.csv`.
2. `scripts\create_bi_windows_users.ps1` creates the local Windows account (random password, never expires), and puts it
   in `HNH_BI_Users`, in the department group `HNH_BI_<dep>` and in the branch group `HNH_BI_Branch_<branch>` of every
   branch the user can see (all eight without `branch_key`). The script only adds memberships; after moving a user
   to another branch or department, remove the old group membership by hand. New passwords go to `C:\HNH\secrets\` (Administrators
   only): `bi_user_passwords.csv` to hand out, `bi_user_credentials.xml` for `test.ps1`.
3. `scripts\load_bi_users.ps1` (ClickHouse admin login) replaces `default.bi_users` and `default.map_bi_user_permission`
   with the CSV, after copying the old rows to `*_backup_<timestamp>` tables.
4. After the next dbt build and `process.ps1 -Mode Daily`, the measure `_Measures[Current User]` (folder Diagnostics) in a report shows `HNHANALYTICSSRV\<user>`.

Model administrators (role `HNH Admins`, no row filters) are listed in `$admins` in `scripts\deploy.ps1`, which adds
them to `HNH_Analytics` and `HNH_Analytics_Test` after every deploy.

A row without `branch_key` sees every branch, Head Office included: `load_bi_users.ps1` loads it with `IsAdmin = 1`. Its
specialty restriction and its pay and PII flags still apply.
