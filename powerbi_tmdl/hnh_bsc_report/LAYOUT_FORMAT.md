# Report/Layout format notes

Observed in a legacy Report Server pbix (the BSC handover). Used by the generator code in this folder.

Package parts: `Version` (UTF-16 "1.28"), `[Content_Types].xml` (UTF-8 with BOM), `DiagramLayout`, `Report/Layout`, `Settings`, `Metadata`, `SecurityBindings`, `DataModel` (stored, uncompressed, import model), `Report/CustomVisuals/<visualId>/package.json` and `.../resources/<visualId>.pbiviz.json`, `Report/StaticResources/RegisteredResources/*.png`. No `Report/definition`. A live-connection file has `Connections` instead of `DataModel`.

`Report/Layout` is UTF-16 LE, no BOM, one JSON object. Top-level keys: `id` (0), `resourcePackages` (list; RegisteredResources items `{name, path, type:100}`), `sections`, `config` (JSON STRING), `layoutOptimization` (0). Report `config` string holds `version` ("5.73"), `themeCollection.baseTheme` (e.g. CY26SU05 with visual/report/page versions), `activeSectionIndex`, `defaultDrillFilterOtherVisuals`, `settings`, `objects`. A custom theme applied via Browse for themes appears under `themeCollection.customTheme` plus a `resourcePackages` SharedResources entry (not seen in the handover; confirm in the template).

Page (`sections[i]`) keys: `id` (string index), `name` (20-hex id, or `ReportSectionN` style), `displayName`, `filters` (JSON STRING, "[]" when empty), `ordinal` (string), `config` (JSON STRING; "{}" for plain pages; drill-through pages carry their drill settings here), `displayOption` ("1"), `width`, `height` (1920x1080 in the handover), `visualContainers`.

Container keys: `x, y, z, width, height` (floats, canvas pixels), `config` (JSON STRING), `filters` (JSON STRING), `tabOrder` (optional). Hidden helper buttons are parked at x=y=-5000, 1x1.

Container `config` (parsed): `name` (20-hex, unique id), `layouts: [{id:0, position:{x,y,z,width,height,tabOrder}}]` (position duplicated from the container keys; keep both in sync), `singleVisual`, and sometimes `howCreated`. `singleVisual` keys: `visualType` (`textbox`, `image`, `actionButton`, `slicer`, custom visuals as `<name>_PBI_CV_<GUID>`; built-ins like `card`, `tableEx`, `pivotTable`, `clusteredBarChart`, `lineChart`), `projections`, `prototypeQuery`, `columnProperties`, `drillFilterOtherVisuals`, `objects`, `vcObjects`.

Field references: `projections` maps a role name (slicer `Values`; the custom visual's `dataset`) to `[{queryRef, active?}]`. `queryRef` equals the `Name` of an entry in `prototypeQuery.Select`, `"<Entity>.<Property>"`. `prototypeQuery` = `{Version:2, From:[{Name:"t0", Entity:"<table>", Type:0}], Select:[{Column|Measure:{Expression:{SourceRef:{Source:"t0"}}, Property:"<col>"}, Name:"<Entity>.<Property>", NativeReferenceName:"<display>"}]}`; optional `Where`, `OrderBy`. `columnProperties[queryRef].displayName` renames a field. Literals in `objects`/`vcObjects` are `{"expr":{"Literal":{"Value":"'text'"}}}` (strings single-quoted; numbers `16D`; bools `true`). Colors: `{"solid":{"color":{"expr":{"Literal":{"Value":"'#2FA5E3'"}}}}}`. Each object is a list of `{properties, selector?}`. Container chrome is `vcObjects` (`title`, `background`, `border`, `visualHeader`). The custom visual's script lives in `objects.general[0].properties.js` as a quoted literal.

## Generator shapes (Task 4)

Sources checked on this server, read only: the handover pbix; `D:\hnh_analytics_model_explore.pbix` (a live-connection report on `HNH_Analytics_test`, written by Desktop); `powerbi_tmdl\test isual.pbix` (Desktop for Report Server, live on the `Balanced Scorecard` perspective); `Downloads\test connector.pbix`. "Seen" = the shape is in one of these; "standard" = the documented layout format, with no example on this server. Each standard shape is written by one function in `layout.py`, so it can be fixed in one place once the real template shows it.

Correction to the page notes above: Desktop writes the page `id`, `ordinal` and `displayOption` as numbers, not strings (all four files).

- **Live connection** (seen, `test isual.pbix`): `Connections` = `{"Version":1,"Connections":[{"Name":"EntityDataSource","ConnectionString":"Data Source=localhost\\reportserverdb;Initial Catalog=HNH_Analytics_Test;Cube=\"Balanced Scorecard\"","ConnectionType":"analysisServicesDatabaseLive"}]}`, UTF-8 with no BOM and no `PbiModelDatabaseName`. Desktop keeps the server name as typed (`localhost\reportserverdb`). The build sets `Data Source` to `HNHANALYTICSSRV\REPORTSERVERDB` with `set_server` (the `--server` option), so a downloaded copy also works on other machines, and sets `Initial Catalog` with `set_database`. Other fields are rewritten only when they equal the old value.
- **prototypeQuery** (seen): `{"Version":2,"From":[{"Name":"d","Entity":"Department","Type":0},{"Name":"_","Entity":"_Measures","Type":0}],"Select":[{"Column":{"Expression":{"SourceRef":{"Source":"d"}},"Property":"Department Name"},"Name":"Department.Department Name","NativeReferenceName":"Department Name"},{"Measure":{...,"Property":"Revenue"},"Name":"_Measures.Revenue","NativeReferenceName":"Revenue"}]}`. Desktop's aliases are the table's first letter in lower case (`_` for `_Measures`), then `p1`, `p2` for the next table with the same letter. `layout.aliases` writes them the same way.
- **projections** (seen): `{"Category":[{"queryRef":"Department.Department Name","active":true}],"Y":[{"queryRef":"_Measures.Revenue"}]}`. Category and slicer columns carry `active: true`. The generator copies the other keys of the sample's item at the same position (so `active` is kept) but never `showAll`. In a matrix (`pivotTable`), every `Rows` level gets `active: true`, so all levels show expanded.
- **Sort** (seen): `prototypeQuery.OrderBy = [{"Direction":2,"Expression":{"Measure":{"Expression":{"SourceRef":{"Source":"_"}},"Property":"Revenue"}}}]`. `Visual.sort_dir` sets Direction: "desc" (2, the default) or "asc" (1, for time axes). The sort field must be one of the visual's fields. With a sort the generator removes `hasDefaultSort`; without one it keeps the sample's `hasDefaultSort` and writes no `OrderBy`.
- **Slicer sync** (seen): `singleVisual.syncGroup = {"groupName":"bsc Branch.Branch Name","fieldChanges":true,"filterChanges":true}`. There is one group per field (`"bsc " + Table.Field` of the slicer's first field). The same slicer syncs across pages, and slicers on different fields never sync with each other.
- **Leftovers of the sample's fields** (seen): container-level `query` and `dataTransforms` (Desktop's cached query), `columnProperties`, `expansionStates`, `cachedFilterDisplayItems`, `objects.general[].properties.filter` (a slicer's selection), and `objects` entries whose `selector.metadata` names a field. The generator drops the caches and keeps `columnProperties` only for the new fields. It reads every field reference (Entity + Property, or a From alias + Property) in the sample's `objects` / `vcObjects` and other `singleVisual` keys, including fields that are not in its query, such as conditional formatting on another measure. A **property** naming a field that the new binding does not have is removed, and static formatting in the same entry stays. An **entry** is removed when its selector names such a field, or when it held only such properties. Other `singleVisual` keys naming such a field are dropped. References to bound fields are kept, so the relative-date slicer keeps "this calendar year" when it is bound to `'Date'[Date]` again. The drill button's `drillthroughSection` measure is removed too; set it again through `Visual.props`.
- **Title** (seen): `vcObjects.title[0].properties` `{show, text}`. With `title=None` the generator removes `text` and sets `show` to false. A `sample:` Alt text is removed as well.
- **Button action** (seen, handover): `vcObjects.visualLink[0].properties` `{show, type:'PageNavigation', navigationSection:'<page name>'}`, under **vcObjects**, not objects. `Visual.props` merges into whichever of `objects` / `vcObjects` already holds that object name.
- **Visual and page filter, column** (filter body seen in a slicer's selection; the filter entry is standard): `{"name":"<20 hex>","expression":{"Column":{"Expression":{"SourceRef":{"Entity":"Branch"}},"Property":"Is Hospital"}},"filter":{"Version":2,"From":[{"Name":"b","Entity":"Branch","Type":0}],"Where":[{"Condition":{"In":{"Expressions":[{"Column":{"Expression":{"SourceRef":{"Source":"b"}},"Property":"Is Hospital"}}],"Values":[[{"Literal":{"Value":"'Yes'"}}]]}}}]},"type":"Categorical","howCreated":1}`. The `{name, expression, type, howCreated}` entry and the `Comparison` condition are seen. Literals: `'text'` (quotes doubled), `12L`, `1.5D` (always plain decimal, never an exponent: `0.0000001D`), `true`, `null`.
- **Visual filter, measure** (standard): `type "Advanced"`, Where `{"Comparison":{"ComparisonKind":0,"Left":{"Measure":{...Source}},"Right":{"Literal":...}}}`.
- **Is not blank** (standard, `Filter(field, "notblank")`, column or measure): `type "Advanced"`, Where `{"Condition":{"Not":{"Expression":{"Comparison":{"ComparisonKind":0,"Left":<field, Source form>,"Right":{"Literal":{"Value":"null"}}}}}}}`.
- **Top N** (standard, `layout.top_n_json`): `{"name","expression":<column, Entity form>,"filter":{"Version":2,"From":[{"Name":"subquery","Expression":{"Subquery":{"Query":{"Version":2,"From":[<column table>,<measure table>],"Select":[{"Column":{...Source},"Name":"field"}],"OrderBy":[{"Direction":2,"Expression":{"Measure":{...Source}}}],"Top":15}}},"Type":2},{"Name":"d","Entity":"Department","Type":0}],"Where":[{"Condition":{"In":{"Expressions":[{"Column":{...Source d}}],"Table":{"SourceRef":{"Source":"subquery"}}}}}]},"type":"TopN","howCreated":1}` in the visual's `filters`. It keeps the top N of the visual's first column, ranked by the `top_n` field, which must be a measure.
- **Drill-through** (standard, not seen; `layout.drill_through`): no example on this server. The generator copies the template's `Drill sample` page and does not write the binding from scratch. It takes the binding from a root `pods` entry whose `boundSection` is that page (`{"name","boundSection","config","parameters":"<JSON string>","type"}`) or from the page config's `pageBinding` (`{"name","type":"Drillthrough","parameters":[...]}`). It writes one parameter per drill field, `{"name":"Param_<filter>","boundFilter":"<filter>","fieldExpr":{"Column":{"Expression":{"SourceRef":{"Entity":"Branch"}},"Property":"Branch Name"}}}`, and a matching page filter cloned from the sample's drill filter: `{"name","expression":<field>,"type":"Categorical","howCreated":5}`, with no `filter`. Every other key of the binding and the page config is kept as the template has it. That is how "keep all filters" (`acceptsFilterContext` or similar) carries over. A page with `keep_filters` off (the family pages) gets `"acceptsFilterContext":"None"` (PBIR's name) in the pod's `config` or on the pageBinding (`layout.keep_filters_off`, not seen in a real file). Each binding (pod or pageBinding) gets a unique name, `stable_id(page name, "pod")`. If the template has neither form, the build stops with an error.
- **Hidden page** (seen, handover): page `config` `{"visibility":1}`.
- **Bookmarks** (standard): report `config.bookmarks` (`{name, displayName, explorationState.activeSection}`; groups hold `children`). The build drops bookmarks whose `activeSection` is not a generated page, and drops groups left empty.
- **Show items with no data** (standard): `singleVisual.showAllRoles` / a projection item's `showAll`. The generator never writes either, and `show_all_on_branch` fails the build if one appears on a `Branch` field.

## PBIR (Task 10, `pbir.py`)

The project the generator writes, `HNH Balanced Scorecard.pbip` + `.Report/` + `.SemanticModel/`. Sources: **handover** = `Hayat BSC Deliverable/00_Full Access/Hayat_BSC_Full_RS.*` (Desktop-written PBIR); **Desktop** = Power BI Desktop 2.158 on this server, read offline: the packaging library `Microsoft.PowerBI.Packaging.dll` (project reader, artifact types and their JSON property names, constants), the report schemas embedded in `Microsoft.PowerBI.ClientResources.dll`, and the report theme schema in `WebView2Resources/minerva/scripts`; **test isual** = `test isual.pbix` (Desktop for Report Server, live on the perspective); **legacy** = the shapes above. `pbir_check.py` re-runs the two Desktop checks: the report JSON against the embedded schemas, and the project through Desktop's own reader (`tools/open_pbip.ps1`).

Files are UTF-8 with no byte-order mark, 2-space indented, with CRLF line ends (handover). `$schema` URLs are the handover's: pbip `pbipProperties/1.0.0`, pbir `definitionProperties/2.0.0` (version `4.0`), `.platform` `platformProperties/2.0.0`, pbism `semanticModel/definitionProperties/1.0.0` (version `4.2`), `versionMetadata/1.0.0` (version `2.0.0`), `report/3.3.0`, `pagesMetadata/1.1.0`, `page/2.1.0`, `visualContainer/2.12.0`. Desktop 2.158 embeds `visualContainer/2.13.0`. Its schema patterns accept any `2.x.y`, so the validator checks 2.12.0 files against 2.13.0.

- **Live connection** (Desktop). In `definition.pbir`, `datasetReference.byConnection` holds only `connectionString`. The library describes it as a Fabric model only: "Connections to other Analysis Services semantic models must use a byPath reference to a semantic model definition containing a modelReference.json file". `PBIProjectUtils.GetConnectionTypeFromDatasetConnectionString` returns nothing for an SSAS string. The project therefore writes `"datasetReference":{"byPath":{"path":"../HNH Balanced Scorecard.SemanticModel"}}`. The model folder holds `.platform`, `definition.pbism` (`{"$schema","version":"4.2","settings":{}}`, handover) and `modelReference.json` at its root. Desktop's reader asks for that path when the folder has no model. `modelReference.json` = `{"$schema":".../semanticModel/modelReference/2.0.0/schema.json","connectionString":"Data Source=HNHANALYTICSSRV\\REPORTSERVERDB;Initial Catalog=HNH_Analytics_Test;Cube=\"Balanced Scorecard\"","connectionType":"analysisServicesDatabaseLive"}`. The connection string and type are as test isual's `Connections`, with the server name given. The 2.0.0 schema refuses a `version` property. An optional `isMultiDimentional` (sic) is left out, which means tabular. Desktop's validator and reader accept the file, and the reader reports `modelReference=True` with that connection. One function: `pbir.live_connection`.
- **.pbip / .platform** (handover): `{"$schema","version":"1.0","artifacts":[{"report":{"path":"<name>.Report"}}],"settings":{"enableAutoRecovery":true}}`. `.platform` = `{"$schema","metadata":{"type":"Report"|"SemanticModel","displayName"},"config":{"version":"2.0","logicalId":<guid>}}`, with a uuid5 logicalId so a rebuild writes the same one. A `.gitignore` beside the .pbip ignores `**/.pbi/localSettings.json` and `**/.pbi/cache.abf`, as Desktop writes one.
- **report.json** (handover, schema): `themeCollection.baseTheme` `{name:"CY26SU05", reportVersionAtImport:{visual:"2.9.0",report:"3.3.0",page:"2.3.1"}, type:"SharedResources"}`. `customTheme` has the same shape with `name:"hnh_bsc_theme.json"`, `type:"RegisteredResources"` (schema, standard PBIR; no custom theme in the handover). `resourcePackages`: `SharedResources` `[{name:"CY26SU05",path:"BaseThemes/CY26SU05.json",type:"BaseTheme"}]`, `RegisteredResources` `[{name,path:"hnh_bsc_theme.json",type:"CustomTheme"}]`, and the visual's package. The files go in `StaticResources/SharedResources/BaseThemes/CY26SU05.json` (copied from test isual, kept in `theme/`) and `StaticResources/RegisteredResources/hnh_bsc_theme.json`. `objects.section` verticalAlignment `'Top'` and `settings` are as the handover.
- **Private custom visual** (legacy + Desktop constants; not confirmed by a PBIR file). The handover lists its AppSource visual in `publicCustomVisuals` and ships no package. The HNH visual is private, so the project mirrors the pbix: `CustomVisuals/<guid>/package.json` (the .pbiviz's package.json, compact) and `CustomVisuals/<guid>/resources/<guid>.pbiviz.json` (bytes from the .pbiviz). Desktop's reader loads the `CustomVisuals` folder (constants `ReportCustomVisualsName`, `ReportCustomVisualPackageName`). The resource package is `{name:<guid>, type:"CustomVisual", items:[{name:"<guid>.pbiviz.json", path:"<guid>.pbiviz.json", type:"CustomVisualMetadata"}]}`. The legacy pbix stores package type 0 and item type 5, and the schema enums list CustomVisual and CustomVisualMetadata at those positions; the legacy Image 100 = `Image` fits the same mapping. `visualType` is the guid (`hnhBscVisual431F658EE9D44EA3BD5E1BEA5FAF899D`), as in test isual. One function: `pbir.custom_visual`.
- **pages.json / page.json** (handover): `{"$schema","pageOrder":[names],"activePageName":<first>}`. A page is `{"$schema","name","displayName","displayOption":"FitToPage","height":1080,"width":1920}`. A hidden page adds `"visibility":"HiddenInViewMode"` (handover). Page filters go in `filterConfig.filters`. The folder name and `name` are the page's `Page.name`, which navigation buttons target. `Page.interactions` go in `visualInteractions: [{"source","target","type"}]` (page schema 2.1.0 `VisualInteraction`; `type` one of `Default`, `DataFilter`, `HighlightFilter`, `NoFilter`), source and target by the generated visual names; the pillar pages write `NoFilter` from the by-hospital chart to the HNH visual and to the selection label. The legacy routes (`pbir_to_pbix.py`, `layout.page_section`) write them in the page `config` with numeric types (Default 0, DataFilter 1, HighlightFilter 2, NoFilter 3).
- **Drill-through** (page schema; no drill page in any file here): `"type":"Drillthrough"`, `"pageBinding":{"name":<id>,"type":"Drillthrough","parameters":[{"name":"Param_<filter>","boundFilter":"<filter>","fieldExpr":<field>}],"acceptsFilterContext":"Default"}`. The schema describes `Default` as "Flows filter context", which is Keep all filters on; `None` turns it off. KPI detail writes `Default`; the family pages write `None` (`Page.keep_filters`), so only their drill fields arrive. The page filter per drill field is `{"name","field","type":"Categorical","howCreated":"Drillthrough"}` with no `filter`. One function: `pbir.drill_binding`.
- **Filter entry** (handover + schema): `{"name","field":<field, Entity form>,"type","filter"?,"howCreated"}`. These are the legacy entries with `expression` renamed `field`. `howCreated` is a name: legacy 1 = `"User"`, 5 = `"Drillthrough"` (filterConfiguration enum order Auto, User, Drill, Include, Exclude, Drillthrough). The `filter` bodies (In, Comparison, Not, the TopN subquery) are the legacy ones.
- **visual.json** (handover): `{"$schema","name":<20 hex>,"position":{x,y,z,height,width,tabOrder},"visual":{...},"filterConfig"?}`, in folder `visuals/<name>/`. `name` is `stable_id(page, "visual", index)`, and z = tabOrder = index × 1000. `visual` = `{"visualType","query"?,"objects"?,"visualContainerObjects","syncGroup"?,"drillFilterOtherVisuals":true}`.
- **Query** (handover + schema): `query.queryState.<role>.projections[] = {"field":<field, Entity form>,"queryRef":"Table.Field","nativeQueryRef":"Field","active"?}`. There is no prototypeQuery; From aliases appear only inside filters. `active: true` goes on a chart's Category, a slicer's Values (handover) and every matrix Rows level (legacy). Sort is `query.sortDefinition = {"sort":[{"field","direction":"Ascending"|"Descending"}]}`.
- **Formatting objects** (schema): container objects (`title`, `background`, `border`, `visualHeader`, `visualLink`, ...: the visualConfiguration 2.8.0 list) go in `visualContainerObjects`; everything else, including a text box's `general.paragraphs` (handover), goes in `objects`. Titles follow the legacy rule: `title [{show:true,text}]`, or `show:false` when `Visual.title` is None.
- **Buttons** (handover): `visualContainerObjects.visualLink[0].properties` `{show, type:'PageNavigation', navigationSection:'<page name>'}`, `{type:'Back'}`, or `{type:'Drillthrough', drillthroughSection:{expr:{Measure:[BSC Detail Page]}}}`. The label is `objects.text`: `[{properties:{show:true}}, {properties:{text,fontColor}, selector:{id:'default'}}]`. Desktop 2.158's actionButton (BasicShapeVisual bundle) reads `show` from the entry without a selector and every other text property per state (`default`, `hover`, `selected` = press, `disabled`, `loading`); the other states fall back to `default`. A label without a selector is never read: the button rendered blank (Desktop check 2026-10-25). Open detail also styles `disabled` (fill and font colour), shown until a matrix cell is selected. The handover's buttons have no text; the property names are the theme schema's (`text.show`, `text.text`, state `$id`).
- **Text box, tables, bar charts** (Desktop 2.158 bundles and report theme schema): a text box run's style is `textRuns[].textStyle {fontFamily, fontSize:'20pt', fontWeight:'bold'}` (CSS values, as the TextboxVisual bundle reads them). Table text wrap: `objects.values[0].properties.wordWrap` and `objects.columnHeaders[0].properties.wordWrap`. Bar chart: `objects.valueAxis[0].properties.show false` hides the value axis, `objects.labels[0].properties.show true` turns data labels on.
- **Frame: panel, image, theme** (Task 7, `frame.py`). A `panel` is a `textbox` with no `objects` (no paragraphs) and the container `background [{show:true, color:{solid:{color:'#hex'}}, transparency:0D}]`, `border [{show:false}]` (with a radius: show true, the same colour, `radius`, `width 1`, so the corners round without an outline; visualConfiguration 2.8.0 `Border` {show, color, radius, width}) and `visualHeader [{show:false}]`; no Desktop-written shape visual exists on this server. The `image` (handover visual 87a2d5e3b91495a5c391) is `objects.image[0].properties.sourceFile.image {name:'hnh_logo_white.png', url:{expr:{ResourcePackageItem:{PackageName:"RegisteredResources",PackageType:1,ItemName:"hnh_logo_white.png"}}}, scaling:'Normal'}`; report.json registers `{name,path:"hnh_logo_white.png",type:"Image"}` in RegisteredResources and the PNG goes to `StaticResources/RegisteredResources/` (as the handover's `HNH_Header_Brand.png`). Scaling: Desktop's report theme schema (`desktop.reportThemeSchema.json.min.js`) titles `Normal` "Fit" (keeps the aspect ratio) and `Fit` "Stretch". The theme puts no box on `*`: white background and a 1 px `#DCE5EF` border with radius 12 on the data visuals only; the HNH visual's type (its guid; the theme schema allows any visual name) gets background and border off; frame visuals set their own container objects. The theme validates against that schema (`test_theme_matches_desktop_theme_schema`). The legacy template route has no sample for either kind and leaves them out (`layout.NO_SAMPLE`).
- **Slicers** (handover): `objects.data[0].properties.mode 'Dropdown'`. The selection goes in `objects.general[0].properties.filter.filter` (a filter body), with `syncGroup {groupName:"bsc Table.Field", fieldChanges, filterChanges}`. Date range (the seven scorecard pages; KPI detail has no slicers, its filters arrive by drill-through): `data` `{mode:'Between'}` and the saved range as the selection, `Where: [And(Comparison(kind 2 GreaterThanOrEqual, 'Date'[Date], datetime'YYYY-01-01T00:00:00'), Comparison(kind 4 LessThanOrEqual, 'Date'[Date], datetime'YYYY-12-31T00:00:00'))]` (semanticQuery 1.4.0 schema for the filter body; the mode name is Desktop's, not listed in the extracted schemas). The year is the build year (`pages.year_range`, `Visual.date_range`). One function: `pbir.date_range_slicer`. The legacy pbix route has no From - To sample and keeps the template's relative-date slicer (`layout.LEGACY_SAMPLE`).
