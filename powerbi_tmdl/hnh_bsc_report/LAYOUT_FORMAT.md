# Report/Layout format notes

Observed in a legacy Report Server pbix (the BSC handover). Used by the generator code in this folder.

Package parts: `Version` (UTF-16 "1.28"), `[Content_Types].xml` (UTF-8 with BOM), `DiagramLayout`, `Report/Layout`, `Settings`, `Metadata`, `SecurityBindings`, `DataModel` (stored, uncompressed, import model), `Report/CustomVisuals/<visualId>/package.json` and `.../resources/<visualId>.pbiviz.json`, `Report/StaticResources/RegisteredResources/*.png`. No `Report/definition`. A live-connection file has `Connections` instead of `DataModel`.

`Report/Layout` is UTF-16 LE, no BOM, one JSON object. Top-level keys: `id` (0), `resourcePackages` (list; RegisteredResources items `{name, path, type:100}`), `sections`, `config` (JSON STRING), `layoutOptimization` (0). Report `config` string holds `version` ("5.73"), `themeCollection.baseTheme` (e.g. CY26SU05 with visual/report/page versions), `activeSectionIndex`, `defaultDrillFilterOtherVisuals`, `settings`, `objects`. A custom theme applied via Browse for themes appears under `themeCollection.customTheme` plus a `resourcePackages` SharedResources entry (not seen in the handover; confirm in the template).

Page (`sections[i]`) keys: `id` (string index), `name` (20-hex id, or `ReportSectionN` style), `displayName`, `filters` (JSON STRING, "[]" when empty), `ordinal` (string), `config` (JSON STRING; "{}" for plain pages; drill-through pages carry their drill settings here), `displayOption` ("1"), `width`, `height` (1920x1080 in the handover), `visualContainers`.

Container keys: `x, y, z, width, height` (floats, canvas pixels), `config` (JSON STRING), `filters` (JSON STRING), `tabOrder` (optional). Hidden helper buttons are parked at x=y=-5000, 1x1.

Container `config` (parsed): `name` (20-hex, unique id), `layouts: [{id:0, position:{x,y,z,width,height,tabOrder}}]` (position duplicated from the container keys; keep both in sync), `singleVisual`, and sometimes `howCreated`. `singleVisual` keys: `visualType` (`textbox`, `image`, `actionButton`, `slicer`, custom visuals as `<name>_PBI_CV_<GUID>`; built-ins like `card`, `tableEx`, `pivotTable`, `clusteredBarChart`, `lineChart`), `projections`, `prototypeQuery`, `columnProperties`, `drillFilterOtherVisuals`, `objects`, `vcObjects`.

Field references: `projections` maps a role name (slicer `Values`; the custom visual's `dataset`) to `[{queryRef, active?}]`. `queryRef` equals the `Name` of an entry in `prototypeQuery.Select`, `"<Entity>.<Property>"`. `prototypeQuery` = `{Version:2, From:[{Name:"t0", Entity:"<table>", Type:0}], Select:[{Column|Measure:{Expression:{SourceRef:{Source:"t0"}}, Property:"<col>"}, Name:"<Entity>.<Property>", NativeReferenceName:"<display>"}]}`; optional `Where`, `OrderBy`. `columnProperties[queryRef].displayName` renames a field. Literals in `objects`/`vcObjects` are `{"expr":{"Literal":{"Value":"'text'"}}}` (strings single-quoted; numbers `16D`; bools `true`). Colors: `{"solid":{"color":{"expr":{"Literal":{"Value":"'#2FA5E3'"}}}}}`. Each object is a list of `{properties, selector?}`. Container chrome is `vcObjects` (`title`, `background`, `border`, `visualHeader`). The custom visual's script lives in `objects.general[0].properties.js` as a quoted literal.
