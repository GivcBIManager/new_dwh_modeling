# HNH Balanced Scorecard Visual Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private Power BI custom visual, "HNH Balanced Scorecard", that draws the scorecard pages (overview, pillar board, owner view, hospital comparison) from the `Balanced Scorecard` perspective of `HNH_Analytics`, with Power BI's drill-through menu, tooltips and cross-filtering.

**Architecture:** One TypeScript visual (`pbiviz`, D3 v7) with a categorical data view: one row per KPI from `BSC KPI` grouping columns, the scorecard measures as values, and `Branch` as an optional series for comparison mode. Pure modules turn the data view into a view model (parse, format, state, trend), DOM builders draw it, and `visual.ts` wires the host services. Five small SSAS measures give the visual what the KPI rows cannot: the target trend, pillar and overall scores and the pillar trend evaluated once per pillar, and a selection label.

**Tech Stack:** TypeScript, `powerbi-visuals-tools` (pbiviz), `powerbi-visuals-api` (version fixed by Task 1), D3 v7, `powerbi-visuals-utils-formattingmodel`, Vitest + jsdom for tests, esbuild for the screenshot harness, Edge headless for screenshots. SSAS TMDL and the existing `ssas/tools` / `ssas/tests` checks for the measures.

**Spec:** `docs/superpowers/specs/2026-10-20-hnh-bsc-ssas-perspective-analysis.md`, sections 6.4, 6.5, 6.7, 9 and "KPI states shown by the visual"; design reference `docs/superpowers/specs/assets/2026-10-20-bsc-visual-prototype.html`.

## Global Constraints

- Source lives in `powerbi_tmdl/hnh_bsc_visual/`; the package is a private `.pbiviz` imported into the report (spec 6.7).
- Display name `HNH Balanced Scorecard`; font `"Segoe UI", system-ui, sans-serif` (D10).
- Brand defaults (spec 6.7, prototype `:root`): navy `#0A1E32`, navy-2 `#002E5A`, blue `#13ACE3`, blue-dark `#1478BE`, sky `#32A4E5` (data), on track `#0E9F8E`, watch `#EF8B00`, at risk `#DB280A`, no data `#9AA7B5`; surface `#F4F7FB`, card `#FFFFFF`, line `#DCE5EF`, muted `#5B6B7D`.
- No configuration in the visual: KPI list, labels, pillars, objectives, owners, weights, thresholds, formats and directions arrive as `BSC KPI` columns (improvement 1). The format pane holds only the mode, the title texts and the colours.
- States and their words and icons: On track ✓, Watch !, At risk ▼, No data yet –, Parked –, No target – (spec "KPI states"; `BSC State` returns these words).
- Numerator and denominator are **not** shown (user decision 2026-10-21: the KPI Detail page shows the parts).
- Source badge: `Manual entry` only. Spec improvement 6 also names "Oasis + Fusion GL" and "Oasis", but `BSC KPI` has no data-source column (`Value Source` is `measure` / `manual`); a `data_source` column in `map_bsc_kpi` would add them later without changing the visual's design.
- The visual requests no privileges (no web access, no local storage).
- Everything that changes the server waits for the user (CLAUDE.md): the npm install (Task 1, one approval for the global tools and the project packages), SSAS deploys and processing (the user runs `deploy.ps1`, the auto-mode classifier blocks it for Claude), and uploads to the report server.
- Tests: `npm test` (Vitest) in `powerbi_tmdl/hnh_bsc_visual/`; SSAS side `python -m pytest ssas/tools`, BPA, `measure_guards.py --check`.

## Review Focus

1. A KPI with a target but no actual in the selection, and a parked KPI: the tile shows the reason text ("Not yet calculated for this selection", "Definition to be agreed", "Waiting for this month's entry"), never `0`, `NaN` or a bare dash (Task 3 `stateOf` tests, Task 4 tile test).
2. Trend text with empty slots (`";;5;7"`), fewer than two numbers, or a blank target trend: the sparkline draws only the numeric points and no target line; no `NaN` in any SVG path (Task 4 `sparkPath` tests).
3. A guard message instead of a value (`"BSC Actual" can't be analysed by "Patient"` when a user adds an unrelated slicer): the visual shows that message once across the visual, not a number or a state (Task 3 parse test, Task 5 empty-state test).
4. No KPI rows (page filter leaves none) or a very small viewport (300 × 200): an empty-state message, and the rendering-finished event still fires so export and subscriptions do not hang (Task 6 test).
5. Comparison mode for a user who sees one hospital, or a hospital without rows for some KPIs: one column, blank cells shown as "–" with the no-data colour, no crash (Task 5 comparison test).

### Task 2: SSAS measures for the visual

**Files:**

- Modify (generated): `ssas/HNH_Analytics/perspectives/*.tmdl` via `sync_perspectives.py`

**Interfaces:**
- Produces, for the visual's value roles:
  - `[BSC Target Trend]` text: 12 monthly `[BSC Target]` values, same shape as `[BSC Trend]` (oldest first, `;`-separated, empty for blank).
  - `[BSC Visual Pillar Score]` number: `[BSC Pillar Score]` of the row's pillar over all KPIs the visual shows (`ALLSELECTED('BSC KPI')`), returned only on the pillar's first KPI row (lowest `KPI Code` of that pillar in `ALLSELECTED`), blank on the others.
  - `[BSC Visual Overall Score]` number: `[BSC Overall Score]` over `ALLSELECTED('BSC KPI')`, returned only on the first KPI row overall.
  - `[BSC Visual Pillar Trend]` text: 12 monthly `[BSC Pillar Score]` values of the row's pillar, same gating and shape as above.
  - `[BSC Selection Label]` text: `<hospitals> · <period>`. Hospitals: the branch name for one hospital; `Corporate` when every hospital the user may see is selected (`COUNTROWS` of hospitals in context = the count under `ALL(Branch)`, which RLS still limits; spec D5); otherwise `<n> hospitals`. Period: `MMM yyyy` of the first and last date in context capped at today, `Aug 2026` for one month, `Jan 2026 – Sep 2026` for a range.

The gating keeps the query to one pillar computation per pillar instead of one per KPI row:

```
VAR Pillar = SELECTEDVALUE ( 'BSC KPI'[Pillar] )
VAR FirstCode = CALCULATE ( MIN ( 'BSC KPI'[KPI Code] ), ALLSELECTED ( 'BSC KPI' ), 'BSC KPI'[Pillar] = Pillar )
RETURN IF ( SELECTEDVALUE ( 'BSC KPI'[KPI Code] ) = FirstCode, CALCULATE ( [BSC Pillar Score], ALLSELECTED ( 'BSC KPI' ), 'BSC KPI'[Pillar] = Pillar ) )
```
