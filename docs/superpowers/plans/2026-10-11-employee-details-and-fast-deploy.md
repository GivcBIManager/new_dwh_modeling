# Employee Details and Changes-only Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show Fusion employee names in `HNH_Analytics` only to users with pay access, and stop reloading the whole test database on every deploy.

**Architecture:**
- **Employee Details:** a new gold table `dim_employee_pii` (employee key, branch, Fusion `full_name`) is exposed through the view `gold.ssas_dim_employee_pii` as the SSAS table **Employee Details**. It copies the `Patient Details` pattern (decision P27): a many-to-one relationship to `Employee` that cross-filters both ways but applies security one way only, and a row filter that lets only pay users of the employee's branch see a row.
- **Model generation:** the generator gains an offline mode that reads view columns from the dbt contract file. The model can then be regenerated on this server, which has no `clickhouse_connect`.
- **Deploy:** the `deploy.ps1` Test stage keeps `HNH_Analytics_Test` loaded. It deploys metadata only, loads new or changed tables, runs a daily refresh and then the full tests. Promote no longer clears the test database.

**Tech Stack:** dbt-clickhouse (receiving project on the Ubuntu server), ClickHouse 26.5, TMDL / DAX at compatibility level 1700, Tabular Editor 2.27, Python 3.12 + pytest, Windows PowerShell 5.1 + Pester 3.4.

**Spec:** `docs/superpowers/specs/2026-10-07-hnh-ssas-tabular-model-design.md` (sections 5.3, 6.2, 9.5, 10.2, 14 P27, P35, P36) and `docs/superpowers/specs/2026-10-06-hnh-dwh-phase4-workforce-design.md` (section 3, line 66, "Names … are never staged", which this plan amends for one table). User decisions of 2026-10-11:
- Employee names go in a separate table, as with Patient Details.
- Names are visible to `can_see_pay` users.
- Deploys use a changes-only test path, and `HNH_Analytics_Test` stays loaded (about +6 GB SSAS memory).

**Branch:** create `ssas-employee-details` from `ssas-kpi-catalogue`. The catalogue is tested but not yet promoted, so the next promotion carries both.

## Review Focus

1. **A user without pay access must lose nothing but the names.** If the Employee Details row filter reached `Employee` (a one-to-one relationship, or security filtering both ways), every workforce fact would vanish for non-pay users. That is the P27 incident again. Pinned in Task 4 by the security stage's existing per-fact row checks (they cover Headcount, Absences, Worker Movements, …) and by the BPA rules extended to Employee Details.
2. **A pay user sees names only for their own branches,** like the pay facts they can see. Pinned in Task 4 by a new security check: Employee Details rows for a user equal the ClickHouse count for that user's branches when they have pay access, and 0 otherwise.
3. **The offline generator must reproduce the model exactly.** A contract that disagrees with the live view would silently change a column type or drop a column. Pinned in Task 1: `generate.py --from-contracts` on the unchanged config leaves `git diff` empty.
4. **The changes-only test must still load what changed.** A new table (Employee Details) and recent data must be loaded before the tests, and an empty or missing test database must fall back to a full load. Pinned in Task 2 (Pester `Select-HnhTestMode` cases) and in Task 6 (the deploy log shows the mode and the `Employee Details` partition loaded).
5. **An employee whose name is missing in Fusion** must still appear in Employee Details, with a blank name, so the row count equals `dim_employee`. Pinned in Task 3: the `relationships` and row-count check on `dim_employee_pii` (4,800 rows on 2026-10-11, every name present today).

def contract_columns(text: str) -> dict:
    """{view: [Column]} from the dbt contract file _ssas__models.yml, which scripts/gen_view_contracts.py writes from the
    built views; generate.py --from-contracts uses it where ClickHouse is not reachable from Python."""
    views, current, name = {}, None, None
    for line in text.splitlines():
        found = re.match(r"^  - name: (\S+)$", line)
        if found:
            current, name = views.setdefault(found.group(1), []), None
            continue
        found = re.match(r"^      - name: (\S+)$", line)
        if found:
            name = found.group(1)
            continue
        found = re.match(r'^        data_type: "(.*)"$', line)
        if found and current is not None and name is not None:
            current.append(Column(name, found.group(1)))
            name = None
    return views
```

function Select-HnhTestMode {
    # Changes-only test (decision P38): reuse the loaded test database unless -Full is asked for, the database does not
    # exist, or no partition holds data (a cleared or freshly created database).
    param([bool]$Exists, [int]$ReadyPartitions, [bool]$Full)
    if ($Full -or -not $Exists -or $ReadyPartitions -le 0) { return 'Full' }
    return 'Changes'
}

function Get-HnhReadyPartitionCount {
    # Partitions whose data is loaded (state Ready); calculation groups are not counted.
    param([Parameter(Mandatory = $true)]$Model)
    $count = 0
    foreach ($table in @($Model.Tables)) {
        foreach ($p in $table.Partitions) {
            if ($p.SourceType -eq [Microsoft.AnalysisServices.Tabular.PartitionSourceType]::CalculationGroup) { continue }
            if ($p.State -eq [Microsoft.AnalysisServices.Tabular.ObjectState]::Ready) { $count++ }
        }
    }
    return $count
}
```
