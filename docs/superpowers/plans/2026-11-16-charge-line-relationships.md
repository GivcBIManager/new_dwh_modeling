# Charge Line Relationships Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Charge Lines in `HNH_Analytics` gets seven new dimension links: Service Department, Ordering Doctor, MRP 1, MRP 2, MRP 3, Charged By and Policy. Policies are grouped by client company and referral through one config table, and new measures give census, episodes, CPV and CPE by any Charge Lines slicer (product category first).

**Architecture:** Two layers, each gated by the user before anything touches the server.
- **A. Config and dbt:** a change-log table `default.map_policy_client`; new staging columns; new models `int_charge_line_links`, `int_policy_client`, `int_order_line_encounter`, `dim_policy`, `dim_service_department`; new keys on `fact_charge_line` and `fact_order_line`; `ssas_*` views.
- **B. SSAS:** two dimensions and five Staff role copies, wired through `ssas/tools/model_config.py`. Six measures in `Revenue Cycle\By Charges` that move the Charge Lines filter onto Encounters and Episodes with `TREATAS` on hidden keys. There is no fact-to-fact relationship.

**Tech Stack:** dbt (ClickHouse, run in the receiving project on 172.22.25.214); SSAS Tabular TMDL generated by `ssas/tools`; Python 3.12 and pytest; Pester (Windows PowerShell 5.1).

**Spec:** `docs/superpowers/specs/2026-11-16-charge-line-relationships-design.md`

- **Config tables are change logs** (as `docs/bsc_config.md`):
  - insert only; the newest row per key wins;
  - every row ends with `changed_at DateTime64(3), changed_by String, change_note String, is_deleted UInt8`;
  - `ENGINE = MergeTree ORDER BY (<key>, changed_at)`.
  - Apply them through `Invoke-HnhConfigApply` in `scripts/HnhCh.psm1`, the same way as `scripts/hr_config/apply_hr_config.ps1`.
- **Title case (CLAUDE.md).**
  - Wrap `policy_name` and `service_department_name` in `hnh_title`. The fallback client name is title-cased; a `client_company` typed into the config table is used exactly as written (`STC` stays `STC`).

Put any `*_name` column that holds them in the `excluded` list of `hnh_dwh/tests/hnh/assert_mart_text_title_case.sql` only if the test then fails on them. It shouldn't, because those labels are already title case.
- **Keys:**
  - Every new fact key is `Int64`, and `-1` when the code doesn't resolve to a dimension row.
  - Keys are `hnh_surrogate_key([...])`.
  - `encounter_key` = `hnh_surrogate_key(['branch_id', <'OP'|'ER'|'IP'>, <encounter source id>])`, exactly as in `fact_encounter.sql:6` and `fact_charge_line.sql`.
- **Spec values to copy exactly:**
  - Eligibility status `C` is cancelled and skipped.
  - The open end of an eligibility period is `now()`.
  - Tie-break: latest `eligibility_start`, then highest `patient_eligibility_id`.
  - Policy sentinel codes: `-2` `Cash`, `-3` `Deductible`, `-1` `Not Recorded`.
  - `hl7_encounter` prefix `O` → `OP`, `E` → `ER`, `I` → `IP`; the rest of the string is the encounter id. Any other prefix (`X`) falls back to the charge.
- **Measures:**
  - All go in `ssas/HNH_Analytics/tables/_Measures.tmdl`, folder `Revenue Cycle\By Charges`.
  - Edit only between `VAR __Value = ( -- measure body` and `) -- end of measure body`.

  - Every measure needs a `///` description, a format string and a check in `ssas/tests/measures/revenue_cycle.json`.
- **Unchanged:** `Census`, `Episodes`, `Revenue` and every Balanced Scorecard measure. Referral episodes per branch and month must be identical before and after GATE G1.

## Review Focus

1. **A visit with many charge lines counts once.** A visit with 30 Lab lines is one visit in `Census (Charged)`. *Task 8: check `Census (Charged), Lab, branch 1, 2026-10` against a SQL `count()` over encounters `in (select encounter_key …)`, never a join.*
2. **A Department slicer acts on the charge side only.**
   - Department = Radiology counts visits that had a Radiology charge, whatever clinic the visit was booked in. The encounter's own department must not intersect.
   - *Task 8 check: `Census (Charged)`, Department = the top delivering department of branch 1 in 2026-10.* Its SQL filters the charge's `department_key` only.
3. **A visit on the last day of a month, charged the next day.**
   - It counts in the visit's month.
   - Its next-day revenue is in that month's CPV.
   - *Task 8 check: `Revenue (Charged Visits)`, branch 1, 2026-09.* Its SQL takes all charges of the September visits, with no limit on delivery date.
4. **"STC" inside another word.** `WESTCON SAUDI COMPANY` and `MISTCA` must not become STC. *Task 3 Pester: `whole-word pattern does not match WESTCON or MISTCA`.*
5. **Speed for a report reader with row security.**
   - `Census (Charged)` for a whole year at network level passes thousands of keys through `TREATAS`.
   - *Task 8 adds `ssas/tests/performance.json` entries for `Census (Charged)` and `Revenue per Charged Visit (CPV)`, one year, all branches, by Product Category.* The threshold is the file's existing one for heavy measures.
   - GATE G2 also reports the model's memory before and after, from the DMV `DISCOVER_OBJECT_MEMORY_USAGE`.

**Interfaces (measure names, exactly):**

Formats: `#,0` for counts and revenue; `#,0.00` for CPV and CPE.

The bodies follow this shape. `Census (Charged)` is shown; the rest mirror it.

```dax
VAR Keys =
    CALCULATETABLE (
        VALUES ( 'Charge Lines'[Encounter Key] ),
        'Charge Lines'[Is Recognised Revenue] = "Yes",
        REMOVEFILTERS ( 'Date' ), REMOVEFILTERS ( 'Time' )
    )
RETURN
    CALCULATE (
        [Census],
        REMOVEFILTERS ( Department ), REMOVEFILTERS ( Staff ), REMOVEFILTERS ( Payer ),
        REMOVEFILTERS ( 'Care Type' ), REMOVEFILTERS ( Patient ),
        TREATAS ( Keys, Encounters[Encounter Key] )
    )
```

- `Episodes (Charged)`: the same, with `Episode Key` onto `Episodes[Episode Key]` and `[Episodes]`.
- `Revenue (Charged Visits)`: the reverse direction.
  - Take the keys of the counted encounters in the current context: the visit-side Date applies; Department, Staff, Payer, Care Type and Patient are removed on the encounter side.
  - Apply them to Charge Lines with `TREATAS`, and drop the Date and Time filters there.
  - The result is `[Revenue]`, so only the charge filters in context count (Lab revenue under Lab).
  - "Counted encounters" means the rows `[Census]` counts. Mirror the filters of `[OP Visits]` and `[ER Visits]` in `_Measures.tmdl` exactly.
- `Revenue (Charged Episodes)`: the same over `[Episodes]`' rows.
- `Census (Ordered)`: like `Census (Charged)` from `'Order Lines'[Encounter Key]`, with no recognised-revenue filter.
